# Home card — the raffle-ticket sign-in screen

_Feature deep-dive extracted from `CLAUDE.md`. That file holds the repo-wide conventions, commands and verification gate; this one holds only the public home card (`app/home-card.tsx`) and its backdrop._

## The ticket

The sign-in card is a "link in bio" `HomeCard` (`app/home-card.tsx`) that flips in place between three modes (`bio` / `signin` / `forgot`) rather than navigating. **It is shaped like a raffle ticket**, and that shape is load-bearing for how you edit it:

- **`BIO_LINKS` owns the order CTA, and `tier` is the layout.** The array is **one entry** — `tier: "prize"`, the full-width gold row (which also takes a `sub` second line), pointing at `/mylar-printing`. `tier: "tile"` (the two-column grid that used to sit beneath it) survives in the type but **nothing renders that tier any more**, so adding a tile entry adds a link no visitor can see. **Exactly one `prize` is expected** — a second spends the accent twice and flattens the hierarchy. `sameTab` is set on in-app routes *and* on any `sms:`-style handoff, since an OS-handled navigation opened with `target="_blank"` strands an empty tab behind it. `sticky` marks the single link the phone-only floating CTA mirrors once it scrolls out of view — a flag rather than a second hardcoded href, so the two can't drift.
- **On mobile, a separate “GET IN TOUCH” button sits above the order CTA**, with “CUSTOM DESIGNS INQUIRY/QUESTIONS” below it, opening `sms:+19297528373` in the same tab. It replaces the dotted perforation below `md`. The card and header size to their contents and the shell centres them within `100svh`; do not stretch the header or chain percentage heights through the glass wrappers. A compact scale at 600px viewport height keeps both buttons, the slideshow, and footer visible on small portrait phones.
- **Under the button is `SHOWCASE_IMAGES`, a crossfading slideshow (`ShowcaseSlideshow`).** Entries are paths under `public/showcase/`, cycling in array order every `SHOWCASE_HOLD_MS`; the box **renders nothing at all** while the list is empty and a single entry renders as a still with no timer, so an unfinished set can't ship an empty frame. Images are served straight from `public/` as `unoptimized` and **pre-sized to their display size** (the current set is ten WebP photos, 840px wide; the frame matches the order button’s width) — see the image-optimizer bullet in **Conventions** for why. `.tk-showcase*` styles live in `app/globals.css`.
- **There is no social row and no `SOCIAL_LINKS` array.** The Instagram / Cash App / `sms:` / Chime marks that used to sit in the ticket stub were removed when the page was stripped back to one call to action; the stub is now the positioning line alone.
- **Ticket visuals (`.tk-*`) live in `app/globals.css`; the mobile entrance animation lives in a `<style>` block inside `app/home-card.tsx`.** That block is plain CSS on purpose — the landing page shouldn't wait on framer-motion to hydrate. **Do not animate `opacity` on `.home-enter-card`**: a filling opacity animation promotes it to a Chromium Backdrop Root permanently, which silently kills the card's `backdrop-filter` frost (it computes fine in devtools and never composites). Children fade individually instead. `prefers-reduced-motion` drops travel/sweep/parallax entirely.
- **Responsive sizing is a viewport-height custom-property scale**, not per-element breakpoints: `.home-shell` declares `--home-pad` / `--home-logo` / `--home-link-h` / `--home-cta-room` etc. in `app/globals.css`, re-declared at short-screen heights. Retune the scale rather than adding one-off classes. Scroll-linked parallax comes from `useScrollParallax` (`app/use-home-scroll.ts`).

## The backdrop

The homepage backdrop is **viewport-split**: `HomeMobileBackground` (`app/home-mobile-background.tsx`, a `fixed top-0 h-lvh` plain `<div>` painting `public/home-bg-mobile.webp` as a `bg-cover` CSS `background-image` from a build-hashed static import, so the card scrolls over a still backdrop — **not** a `next/image`, and with **no transform, `will-change` or parallax**: mobile Safari discards a fixed, GPU-promoted image layer sitting beneath a live `backdrop-filter`, revealing the black fallback a few seconds in, which is what the earlier fixed version did. `h-lvh` rather than `inset-0` so the box never resizes as Safari's toolbar collapses. See also the image-optimizer bullet in **Conventions**) below `md`, `AnimatedBackground` from `md` up — handed `public/home-bg-desktop.webp` through its `image` prop, since every other page keeps its default diamonds. The two are mutually exclusive, so change both if you change one; both are the same ICEE print-sheet photo, pre-cropped to phone (900x1600) and 16:10 (2400x1500).
