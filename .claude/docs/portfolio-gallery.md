# Portfolio Gallery & the sibling public galleries

_Feature deep-dive extracted from `CLAUDE.md`. That file holds the repo-wide conventions, commands and verification gate; this one holds only the public gallery pages and their keypad gate._

- **Public page:** `/portfolio` (`app/portfolio/page.tsx`, `force-dynamic`, allow-listed in `proxy.ts`) is a dark-glass gallery of every image in the **public `custom-work` Storage bucket** — reached from the `Portfolio` button in `BIO_LINKS` on the home card. No DB tables, no migrations: images load **dynamically from Storage**, so files uploaded later appear on the next request with no code change.
- **Sibling galleries — one renderer, one bucket each.** Every sibling is the same shape: a `force-dynamic` page that lists a **public Storage bucket** through the generic `listPublicBucketImages()` in `lib/data.ts` (via a thin named helper), then hands the result to the shared `PortfolioGallery` with its own `emptyTitle`/`emptyHint`. **Adding a gallery is: new bucket → 3-line helper in `lib/data.ts` → page → allow-list in `proxy.ts`.** No tables, no migrations.
  - `/taste-budz` (`getTasteBudzImages()`, **`TASTE BUDZ` bucket**) — keypad-gated. The brand logo (`TASTE BUDS READY LOGO.png`) lives *in* the bucket and is the page header + OG/social image, so it's excluded from the grid (the only sibling that filters its own logo out). Share/OG image is self-hosted.
  - `/gso` (`getGsoImages()`, **`GSO` bucket**) — **ungated**, reached by URL only (no home-card button).
  - `/designs` (`app/designs/`) — the **same GSO bucket** behind its own keypad gate, TD Studios `/logo.png` branding.
  - `/mafiaterpz` (`getMafiaTerpzImages()`, **`MAFIA terpz` bucket**) — keypad-gated, `/mafia-terpz-logo.png` branding, `AnimatedBackground`. URL only. **The bucket does not exist in Supabase yet**, so this page renders its empty state until one is created under that exact name.
  - `/whiteash` (`getWhiteAshGallery()`, public **`white-ash-august` bucket**) — **the one sibling that does not follow the rule above.** It never lists the bucket: it `fetch`es a manifest (`data/gallery.json`) the bucket also holds, with `next: { revalidate: 300 }`, so a re-upload appears within five minutes without a deploy and 166 clients hitting the page don't each trigger an origin fetch. The artwork (166 designs, ~77 MB) and the renderer/uploader that produce the manifest **live outside this repo** — publishing a new round touches neither the code nor a redeploy, which is why nothing here writes to that bucket. Images are plain `<img>` **deliberately**: they are already WebP at exactly the two sizes the page uses, so `next/image` would burn billable transformations to produce a slightly worse file. Designs are grouped into *rounds* by their bucket folder (`lib/white-ash-gallery-types.ts` holds the pure label/rank helpers, shared server- and client-side); a malformed manifest degrades to the empty state rather than throwing. Metadata sets `robots: { index: false, follow: false }` — it is unreleased client packaging, shareable by link but out of search.
  - `/premadedesigns` (`getPremadeDesigns()`, private **`premade-designs` bucket**) — the odd one out: it has its own two-view paginated renderer (`DesignsGallery` — a collections index, then that collection's designs, with a lightbox and save-deterrents). The manifest is server-only until the keypad unlocks; only the visible page receives signed image URLs.
- **Keypad gate (`taste-budz` / `designs` / `mafiaterpz` / `martyig` / `premadedesigns`, and — differently — the partner portals):** a lightweight **shared-passcode** gate — deliberately *not* account auth, and unrelated to Supabase Auth or the three roles. Each route owns an `access.ts` (`"use server"`) holding a constant 4-digit code and a `has*Access()` / `enter*CodeAction()` pair backed by an `httpOnly` cookie **scoped to that route's path**, 30-day expiry — so unlocking one page never unlocks another. `/premadedesigns` additionally signs its cookie with a server secret, throttles failed attempts, and uses short-lived Storage URLs because its bucket is private. **The gate is enforced server-side in the page component**, before any fetch, so image URLs / lead rows never reach the HTML until the code is entered — keep it that way; don't move the check into a client component. The shared entry UI is `TasteBudzKeypad` (`app/taste-budz/keypad.tsx`), which takes the server action + logo as props (it defaults to the taste-budz action, so **always pass `action` explicitly** on a new gated route).
- **`/martyig` — "Marty IG Leads" (keypad-gated, not a gallery):** ~1,750 Instagram followers scraped from `@martydetroit`, imported as a **static `app/martyig/leads.json`** (`{ name, username }`) — a plain build-time import, **no DB and no relation to the removed Instagram Leads CRM** (`0005`/`0020`) despite the subject overlap. The page renders `StatCard` totals; `martyig-table.tsx` is a client component doing all search / sort / named-only filter / pagination (50/page) in memory over the imported JSON. Refresh the data by replacing the JSON. Solid black background (no `AnimatedBackground`) for table readability.
- **Image source:** `getPortfolioImages()` in `lib/data.ts` lists the bucket (paginated past the 100/list cap), filters to image files, and resolves each to a public URL via `getPublicUrl`. Listing `storage.objects` is RLS-gated even for a *public* bucket, so it prefers the **service-role** client (falls back to the cookie client, then `[]`) — see the admin-client note. Never hardcodes URLs.
- **Shared model:** `lib/portfolio.ts` (server- and client-safe, no Supabase imports) holds `PortfolioImage`, the data-driven `PORTFOLIO_CATEGORIES` (`all`/packaging/logos/websites/branding/mockups), keyword-based `categorizeImage()` (path/folder → category, defaults `all`), and the pure `filterPortfolioImages()`/`countByCategory()` helpers. Categories are derived, not stored — uploading `logos/acme.png` auto-tags it. **The filter/search helpers are currently unused by the UI** (the bar + search were removed) but kept here so they can be reintroduced without touching the renderer.
- **Client UI:** `app/portfolio/portfolio-gallery.tsx` (a plain CSS-columns masonry grid over all images, 2-col mobile → 4-col desktop — no filter/search bar today; **shared by every sibling gallery**, so its empty state is prop-driven via `emptyTitle`/`emptyHint` — changes here hit all of them), `portfolio-image-card.tsx` (skeleton shimmer, native lazy-load + async decode, aspect-ratio reserved then snapped to the image's true ratio, hover lift/zoom + glass overlay), and `portfolio-lightbox.tsx` (framer-motion fullscreen modal: prev/next, keyboard arrows, Esc, click-outside, mobile swipe, `n / total` counter, blurred backdrop, body-scroll lock). Structured so favorites, collections, downloads, password-gated sets, AI search, and infinite scroll are additive.

## `/premadedesigns` in full

The public route is server-gated by the shared 4-digit keypad (the literal code lives in `app/premadedesigns/access.ts` — it is deliberately not repeated in documentation) and a signed httpOnly cookie. **It is reached by URL only** — the home card's "Premade Designs" tile deliberately points at the Instagram grid instead, so don't "fix" that href to `/premadedesigns`. Only unlocked sessions receive the private `premade-designs` bucket manifest and one-hour signed URLs for whatever is currently on screen. The complete 2,312-image manifest comes from the service-role-only `list_premade_design_paths()` RPC, is cached for 60 seconds, and powers the whole gallery client-side. **It is a two-view gallery, not a flat grid:** the index shows one box per bucket folder (94 of them) with a cover image and a design count, and clicking one opens that collection's designs. `buildPremadeCollections()` in `lib/premade-designs-types.ts` is pure and shared — the page calls it to know which covers to sign, the client calls it to render — so both always agree on a folder's cover. **Only the visible view is ever signed**: 24 covers on the index (`PREMADE_COLLECTIONS_PAGE_SIZE`), 36 designs inside a collection (`PREMADE_DESIGNS_PAGE_SIZE`), and `getPremadeDesignUrlsAction` caps one request at the larger of the two. Search is contextual — collection names on the index, design names inside a collection — and a bucket with one folder (or none) skips the index entirely. **Every bucket image carries the TD Studios watermark** (`DesignWatermark` in `gallery.tsx`) at 85% opacity — design cards, collection covers, and the lightbox alike. It is `pointer-events-none`, so it never steals the card's click or the lightbox's close-on-backdrop, and it sits *under* the right-click deterrent span rather than replacing it. Its asset (`public/premade-watermark.png`) is pre-resized to 800px wide on purpose: like everything else in this gallery it renders `unoptimized`, so whatever is committed is what ships to every card. Its `next/image` instances deliberately set `unoptimized`, so browsers fetch the signed Supabase URLs directly; the production Vercel Image Optimization endpoint currently returns `OPTIMIZED_IMAGE_REQUEST_PAYMENT_REQUIRED` and must not sit in this gallery's delivery path.
